# 赛道图（trackmap）

新看板 id：`trackmap`（导播台下拉里叫「赛道图」）。**原来的「赛段状态」圆环 `ring` 未改。**

这一版车位是**估计**，面板标题旁有红色「估计」标记。轮廓来自本地 SVG，车位来自计时。不用官方 `Position.z`，也不请求 OpenF1。

## 轮廓

只读当前场次赛道的本地 SVG：`web-override/circuits/*.svg`（[f1db](https://github.com/f1db/f1db)，CC BY 4.0）。采样成折线，作为估计车位的弧长坐标。

`CIRCUIT_SVG` 里的每条赛道都有对应文件，所以不再用 OpenF1 历史 `/v1/location` 当后备。名字对不上时，画面写「未识别赛道：…」，不联网。SVG 拉取失败时写「估计 · 轮廓加载失败」，并隔几秒再试。

轮廓文件的起点不一定是起跑线。`CIRCUIT_PHASE` 里写 `offset`（沿路径走到计时线的弧长比例）和 `reverse`（比赛方向是否和文件方向相反）。`sectors` 是相对计时线的 `[S1 终点, S2 终点]`；没写的赛道赛段仍三等分。

`CIRCUIT_SVG` 里除巴林以外的赛道都已写上相位。方格旗仍只画在**进度 0**（`paintTrackmapFinish` + `finishGrid` 的 4×2 小格，大约一条描边那么宽），offset 把进度 0 转到计时线之后，旗就在计时线上，没有第二套旗。

相位是离线校准的，不是运行时请求。做法和奥斯汀那次对照一样：用运行时的 `outlineFromSvg`（并像 `loadSvgOutline` 那样把 y 取负），对 [MultiViewer](https://api.multiviewer.app/api/v1/circuits/) 的中心线做相似变换（平移、旋转、均匀缩放；试镜像和反向），再把 `length ≈ 0` 的 marshal light 投到折线上。导播台页面不调用 MultiViewer，也不调用 OpenF1。重算用 `node director/calibrate-circuit-phase.js`（需要事先放好的 JSON 缓存）。键、年份、置信度和取舍记在 `web-override/circuit-phase-notes.md`。

奥斯汀 `austin-1.svg` 逆时针，和比赛方向一致，`reverse` 仍是 **false**。文件起点在 **T11**：原始弧长 0 到大约 0.20 是 T11→T12 的大直线。计时线在另一条直道上，T20（原始约 0.504）和 T1（原始约 0.651）之间、靠近 T20，进度 0 保持原始弧长 **0.522**。这次重投影大约是 **0.537**（先前的对照是 0.536），两点都在 T20–T1 主直道上，所以不改手调值。S1 终点约在 T6 与 T7 之间（相对计时线 **0.311**），S2 终点在 T12 之后（相对计时线 **0.715**）。

巴林 `bahrain-3.svg` 的采样轮廓和萨基尔大奖赛中心线对不上（相似变换残差大约是周长的 9.7%），没有写相位，进度 0 仍是文件起点。`marina-bay.svg` 和 `marina-bay-4.svg` 是同一个文件，名字表只用后者。

## 车位怎么估

逻辑在 `web-override/trackmap-estimate.js`。

- **练习 / 排位**：每辆车用自己的 S1–S3。没有单独相位数据时，已写出的赛段算走完三分之一圈；`CIRCUIT_PHASE.sectors` 有值时改用那两个终点。当前赛段里已点亮的迷你赛段（2048 / 2049 / 2051）再把这一段细分。迷你赛段状态会褪成 0，这时只把「赛段起点」当成下限，不把车拉回去。
- **正赛 / 冲刺赛**：领先者仍用赛段。其余车用相对领先者的时间差 ÷ 参考圈速（最快圈，否则三赛段之和，否则 90 秒）。`1 LAP` 这种被套圈不用时间差，改回该车自己的赛段。
- 两次计时之间按参考圈速沿轮廓往前走，所以点会动，而不是只在赛段刷新时跳。
- **进站**（`inPit` 或差距文案含 PIT）：运动仍冻在进站那一刻的估计进度，但**画面不画在轮廓上**。所有进站车收到同一块屏幕坐标 P 区：红底「P」徽章 + 车队色点/缩写网格（`tm-car tm-pit`）。锚点优先在进度 0（起终点）沿内侧法向（指向质心）推开。`placePitBay` 用屏幕折线量盒子和点的最短距离，要求 **≥ 1.5× 赛道描边宽度**（描边一半 + 一截可见空隙），所以不会压在灰线上；还不够就继续往里推、扫视口网格，或把格子缩小一号，再不行落到能让开轮廓的视口角。不是真实维修区几何。出站后回到轮廓上的原有画法。
- **出站**（`pitOut` 且 S1 还没有迷你赛段）：沿用当前进度慢慢爬，红虚线圈，仍在赛道上。
- **停车**冻结。**退赛 / 淘汰**不画。
- 场次状态文案里若出现安全车 / 虚拟安全车 / 红旗，整圈时钟会变慢或停住。没有单独的安全车坐标。

车标节点按车号创建一次，之后只改 `transform`（以及颜色、缩写、进站类名）。轮廓路径只在缩放、平移、旋转或尺寸变化时重写 `d`。旗语只改已有区段路径的 `stroke` / `display`。

## 旗语上色

数据就是圆环和旗语栏已经在用的 `state.track` / `state.ring`（jar 的 TrackState），不请求 OpenF1。

| 来源 | 画法 |
| --- | --- |
| `yellowSectors` 里的区段号 | 该段亮黄 `#fdd835`（日间 `#f9a825`） |
| `doubleYellowSectors` | 该段深黄 `#ff9800`（同一区段双黄优先） |
| `globalLevel` 4 虚拟安全车 | 整圈浅金 |
| `globalLevel` 5 安全车 | 整圈琥珀；局部黄旗仍叠在上面 |
| `globalLevel` ≥ 6 红旗 | 整圈红 `#e10600`。官方红旗会清掉分区，没有「某一段红旗」 |
| `globalLevel` 2 且两个区段列表都空 | 整圈黄（只有「有黄旗」、没有区段号时） |

区段数用 `ring.count`（与圆环相同）。每一段占圈程的 `1/count`，区段 1 从**进度 0**起，沿估计车位的同一方向排下去。写了相位的赛道，进度 0 是计时线；巴林仍是 SVG 文件起点。这是等分，不是弯道 GPS，也不是计时用的 S1–S3。相位和真实裁判岗可能差一截；相对顺序与圆环一致。

## 自测

1. `director/Start.cmd`（或 `Publish-Web.cmd`）发布后打开导播台，加一块「赛道图」。改完前端请 **硬刷新**（Ctrl+F5），否则 iframe 可能还拿着旧的 `app.js`。
2. 有场次且赛道能对上本地 SVG 时，应看到闭合轮廓和车位。顶栏文字只有「估计」，旁边是旋转控件。有黄旗区段时，对应的一段轮廓变黄；红旗或安全车时整圈变色。计时里有车 `inPit` / 差距含 PIT 时，这些车只出现在轮廓内侧的 P 区，不该再挤在灰线上。仓库 `docs/pit-bay-*.png` 和 `docs/trackmap-flags-contact-sheet.png` 是默认 zoom 下的估计图示意，README 效果图一节有拼贴。
3. `node director/web-override/trackmap-estimate.test.js`
4. `node --check director/web-override/app.js`

## 还不准的地方

- 写了 `sectors` 的赛道用 FIA 赛段里程（或图例里相对弯心的计时环）投到示意图上。没写的仍按圈程三等分，不是官方测距桩。斯皮尔伯格的示意图拉得比较开，赛段终点没有采用。
- 没有 GPS，统一 P 区、进站弯、安全车列车都对不齐真实赛道。
- 巴林的本地轮廓对不上大奖赛中心线，起跑线仍是文件起点。其余已校准赛道的进度 0 在计时线附近，示意图本身仍有拉伸。
- 正赛时间差在进站、被套圈、虚拟安全车时会漂；数据一更新会再靠拢。
